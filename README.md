# AI R&E Lab

GPT·Claude·Gemini·Grok이 네 사람의 BAZE 키로 공동 AI 연구를 진행하는 연구실입니다. 1415·1314·1410·1411은 같은 권한으로 대화를 읽고 개입하며 자료를 올리고 검토 결정을 내립니다.

## 연구 흐름

전북과학고 [2026학년도 연간계획표](https://school.jbedu.kr/ejbs/M0103030302/)에 표시된 **과제연구 계획서 발표 → 중간발표 → 최종발표** 순서를 기본 뼈대로 삼았습니다. 공개 자료에서 확인되지 않은 학교별 세부 양식이나 정확한 마감일은 임의로 만들지 않습니다.

1. 네 모델이 역할과 AI 연구 주제·질문을 협의합니다. 토론 횟수는 고정하지 않습니다. 주제 변경 시 이유와 이전 결과에 미치는 영향을 기록하고 계획서 검토를 다시 받습니다.
2. 모델들이 계획을 토론하고 **연구계획보고서(.docx/.md), 계획발표 PPT(.pptx), 발표 대본(.md)**을 만듭니다. 사람이 승인하거나 수정 요청을 남깁니다.
3. 승인 뒤 모델들이 실험을 설계합니다. 생성한 실험 사례는 `AI_GENERATED`, 실제 BAZE 모델 응답은 `OBSERVED_BAZE`, 관찰값을 재표본추출한 부트스트랩은 `SIMULATED_RESAMPLING`으로 명확히 기록합니다. 사례별 네 모델의 응답은 독립적으로 수집하며 원본 응답·프롬프트·모델 ID·사용량을 저장합니다. 모델들이 추가 토론·실험을 원하는 만큼 반복할 수 있습니다.
4. **중간발표 PPT·대본**을 만들고 검토를 받습니다. 승인 뒤에도 추가 실험을 할 수 있습니다.
5. **최종보고서(.docx/.md), 최종발표 PPT·대본**을 만들고 최종 검토를 받습니다. 최종 승인을 받아야 완료됩니다.

각 검토는 네 사람 중 누구나 승인하거나 피드백을 담아 수정 요청할 수 있습니다. 내부 사고 과정은 제공업체가 공개하지 않으므로 볼 수 없지만, 앱에서 보낸 프롬프트, 받은 답변, 호출 시각·모델·사용량·오류 및 결과 파일은 활동 기록과 전체 ZIP에 남습니다.

**연구 현황** 탭은 저장된 전체 대화 원문을 읽어 누적 발언 수, 단계별 핵심 발언, 진행 결정, 참여자 의견과 네 AI의 역할·현재 작업을 보여 줍니다. 핵심 발언은 원문에서 발췌하므로 추가 API 비용이 들지 않으며, 상세한 원문은 활동 기록과 ZIP에서 확인합니다.

모델이 만든 문헌·수치·해석은 자동으로 사실이 되지 않습니다. 출처를 등록해 실제 자료를 확인하고, 결과물을 사람이 검토해야 합니다. 문자 수 지표는 답변 품질을 뜻하지 않습니다. AI가 임의 Python 코드를 컴퓨터에서 실행하지는 않으며, 실험 도구는 BAZE 모델 비교와 재현 가능한 부트스트랩 분석으로 제한합니다.

## 일별 예산과 자동 재개

모델을 호출하기 전 담당 BAZE 키의 `GET /credits/`를 확인합니다. [BAZE 크레딧 문서](https://docs.mindlogic.ai/docs/dcu-ac/api-gateway/reference/credits)의 `total.remaining`은 월별·충전·조직 부여 크레딧을 합한 전체 잔액입니다. 사용자 설정에 따라 **이 전체 잔액이 0이 되기 전까지** 호출을 시도합니다. 0이거나 BAZE가 잔액 부족으로 호출을 거절하면 다음 한국 시간 자정 이후 실제 잔액을 다시 조회합니다. 보충을 추정하지 않습니다. 잔액 조회 실패·기타 호출 오류는 화면에 남깁니다.

Supabase Cron이 매시간 비공개 예약 번호를 증가시키고 무료 Render 서버의 `/healthz?wake=1`을 호출합니다. 서버는 Supabase에 저장된 새 예약 번호를 확인한 경우에만 연구를 이어갑니다. 사이트가 잠들거나 PC가 꺼져도 실행 기회를 얻습니다. 무료 서비스의 유휴 중지, 공급자 장애, 잔액 부족, 모델 응답 중단 등으로 실제 일정은 밀릴 수 있습니다. 재시작 시 유료 호출이 진행 중이었다면 중복 청구를 피하려고 자동 재시도하지 않고 사람의 확인을 기다립니다.

## 사용

사이트: [AI R&E Lab](https://ai-re-lab-chanmin6785.onrender.com/)

1. 각 번호로 로그인합니다. 네 사람 누구나 네 칸의 BAZE 키를 저장할 수 있으며 키 값은 다시 표시되지 않습니다.
2. 각 계정에 GPT·Claude·Gemini·Grok 하나씩 배정하고 그 계정에서 제공되는 모델 ID를 선택합니다.
3. **연구 시작하기**를 누릅니다. 메시지 탭에서 진행 상황을 보거나 의견을 보내고, 활동 기록에서 실제 호출 내용을 확인합니다.
4. 검토 대기 단계에서는 공유 자료의 보고서·PPT·대본을 내려받아 확인한 후 **검토 후 승인** 또는 **수정 요청**을 누릅니다. 자료·출처·데이터셋을 추가할 수 있습니다.
5. 연구 중 모델을 바꾸려면 일시정지하거나 검토/잔액 대기 상태에서 새 모델 ID를 적용합니다. 이전 모델의 발언과 결과는 유지됩니다.

## 파일과 저장

`projects/<연구 ID>/`에 `research/`(역할·주제 변경), `references/`(출처), `datasets/`(사용자 자료·AI 생성 사례), `data/raw/`(대화·프롬프트·원형 응답), `data/processed/`(관찰·지표), `results/`(분석), `presentations/{plan,middle,final}/`(보고서·PPT·대본)가 만들어집니다. Render 재시작 후에도 Supabase의 서버 전용 테이블이 프로젝트 상태와 파일을 복원합니다. 파일 크기와 Supabase 무료 용량 제한은 별도로 적용됩니다. 전체 ZIP을 주기적으로 내려받는 편이 좋습니다.

서버 전용 Supabase secret은 브라우저에 전달하지 않습니다. BAZE 키는 AES-256-GCM으로 암호화해 보관하고 GitHub에 올리지 않습니다. 대화와 업로드 자료는 모델 호출 때 BAZE와 제공업체로 전송되므로 민감한 자료는 올리지 마세요.

## 로컬 실행·검사

Python 3.10 이상에서 `python -m pip install -r requirements.txt` 후 `python app.py --share`를 실행합니다. 클라우드는 `render.yaml`과 `Dockerfile`을 사용합니다. 기존 Supabase 프로젝트에는 `supabase-schema.sql`의 서버 전용 테이블과 `pg_cron`, `pg_net` 확장이 필요합니다.

검사: `python -m unittest discover -s tests -v`
